# 案例記錄：插件匯入 Illustrator 的失敗模式

## 環境與範圍

觀察日期：2026-10-01。插件畫面顯示 Figma to Illustrator / Affinity v3.1.1，目標應用程式為 Adobe Illustrator 2026。以下結論只代表本次匯出包與操作結果，不宣稱所有版本都有相同問題。

## 有證據支持的發現

1. **不是單純缺少字型。** 原始 SVG 的 119 個 text 元素使用 Arial 占位名稱，但伴隨 JSX 中 97 筆文字節點 metadata 保留實際字型與區段資訊。需要先核對插件腳本是否正確完成，以及 metadata 是否套用，而不是直接要求使用者重裝全部字型。
2. **字型顯示名稱與實際名稱不同。** 本機 OTF 與 Illustrator 核對到的 PostScript 名稱為 `LINESeedTW_OTF-Regular`、`LINESeedTW_OTF-Bold`、`LINESeedTW_OTF-ExtraBold` 和 `SourceHanSansTC-Bold`。此清單屬於案例，不能套用到其他品牌或文件。
3. **文字濾鏡與內容消失有關。** 在副本中移除 63 個包含文字的群組 filter 後，先前消失的文字在 Illustrator 恢復顯示。這支持本次文字濾鏡相容性問題，但不代表任何 filter 都應移除；陰影外觀未完整保留。
4. **圖片可在副本嵌入。** 匯出包包含 31 張 PNG。嵌入後 SVG 中仍保留 31 個 image 元素，畫面上的商品圖與背景恢復顯示。元素數量只能作為結構驗證，仍需要視覺檢查。
5. **可編輯文字上的 GradientColor 設定未達到預期。** 即使 JSX 建立或取得原漸層並指定至文字 characterAttributes，畫面中的漸層標題仍為黑色。API 沒有報錯不代表外觀正確。
6. **逐字 RGB 可作為近似替代。** 用每個字元的位置估算漸層顏色後，標題由黑色恢復成藍色深淺變化，文字仍是文字物件。這不是字內連續漸層，也不是 1:1 外觀恢復；修改文字後需重新評估填色。今後應先取得使用者對此取捨的同意。
7. **匯入後的物件 ID 未必可靠。** 部分 SVG ID 沒有出現在 Illustrator 父群組名稱。依文字內容與距離可作輔助匹配，但重複文案、多行文字或相同位置會產生歧義；應保留無法對應清單，不要無聲誤配。
8. **空白文字框會造成錯誤驗證。** 僅空白字元的 textFrame 不應被列為缺失文案；應單獨記錄或略過，而非因此阻止所有有效文字交付。

## 操作失敗與改進

- 重跑腳本可能遇到漸層名稱重複。先查既有物件，使用冪等設計；不要盲目新增同名漸層。
- 腳本不能硬編碼 18 個工作區域；本次的 18 只用來對照原始 frames。應先驗證完整資料，再執行文件修改，避免半途錯誤留下部分變更。
- 同時開啟舊 AI 與新 SVG 時，容易把舊檔的缺字畫面當成修正版。每次檢查前確認活動分頁及檔案路徑。
- 儲存的 UI 操作多次返回主畫面，但沒有生成指定 AI；也遇到剪貼簿輸入逾時。應限制無效重試，重新辨識對話框並檢查磁碟，不重複排入儲存操作。
- 不應把不穩定的一次性腳本直接包裝成通用自動修復工具。本 skill 不附本次專案綁定的腳本或設計素材。

## 本次已驗證與未完成的界線

本次報告記錄 129 個非空白 Illustrator textFrames、18 個工作區域及四種預期字型；視覺檢查可見文字與圖片恢復。SVG 的 text 數與 Illustrator textFrame 數不同，可能源於匯入區段拆分，不能直接互相比較判定遺失。

最終 `.ai` 儲存沒有得到檔案存在的證據，也沒有完成重新開檔驗證。原生漸層與陰影未完整恢復。因此本次不能作為「完整、無損轉換已成功」案例；應描述為「文件中恢復可編輯文字與圖片，部分效果採近似方案，儲存待確認」。

## 隱私與可重用性

公開分享時不包含客戶設計、商品圖片、字型檔、Figma 檔案 ID、使用者本機絕對路徑或原始 JSX 的整份內容。新增案例應匿名化，並標示觀察到的版本、證據、取捨與完成狀態。
